## 安装与使用

1. 从 [GitHub Releases](https://github.com/SakuraMurasame/MurasameRTSS/releases/tag/v1.4.1) 下载并安装 `MurasameRTSS-1.4.1.apk`。可覆盖同签名旧版并保留配置与历史记录。
2. 在 Shizuku 中通过无线调试启动服务。
3. 打开 MurasameRTSS，在“监控”页允许悬浮窗和通知，点击“连接 / 授权 Shizuku”。
4. 点击“开始监控”，再切回游戏。可先开启“同时监控应用耗电”（默认关闭，需 Shizuku 授权），下次开始监控时一起记录耗电，停止时保存。单独开启的耗电监控继续运行；隐藏或暂停性能采样不会停止耗电记录，手动停止耗电后须下次重新开始性能监控才会自动启动。
5. 在“样式”页选择暗色、亮色或跟随系统主题，并调整字号、黑底不透明度、顶部间距、分隔线和刷新速度；设置会立即应用。主页也提供字号与黑底不透明度快捷滑块。
6. 在“指标”页开关和排序显示项目。在通知栏可隐藏、暂停或停止；也可添加“性能浮窗”快捷设置磁贴。
7. “记录”页的“监控时自动记录”默认开启：开始监控即记录，停止监控即保存。可同时查看 15 项纵向曲线；关闭开关后也可以手动开始。点任意曲线同步选择时刻，点击“时间范围 / 删除”管理数据。
8. 在“监控 → 应用耗电”或“记录 → 应用耗电记录”开启独立后台耗电监控。首次采样建立基线，下一次采样后显示各程序耗电占比与 mAh；点击程序查看前台 / 后台 / 未归类的分时功耗。可手动选时间范围、历史记录及删除整次记录。详细口径见 [应用耗电说明](BATTERY_MONITOR.md)。

安装包支持 Android 10 及以上，使用项目本地开发证书签名。源码和 APK 不包含签名私钥。自行构建时请妥善保留生成的 `signing/development.jks`，用于更新自己构建的版本；自行构建的 APK 不能直接覆盖不同签名的发布版。

## 语言

在“关于 → 应用语言”选择 **简体中文 / 日本語 / English / Français / Deutsch**。默认跟随系统，其他系统语言回退到英语。设置在重启后保留，切换不停止监控和记录。

翻译包含设置、通知、指标名称、曲线统计、删除提示及更新历史。硬件节点名称和系统原始错误信息保留原值。记录文件中的数值、单位和时间格式不随语言变化，兼容旧记录。

## 数据能力与限制

| 项目 | 本版行为 |
| --- | --- |
| 可用内存、电池温度、电量 | 使用 Android 系统接口 |
| 电池侧功率 | 有效电流 × 电压估算，区分充入 / 输出；不是 CPU/GPU 功耗或充电器功率 |
| 整机功耗 | 未接充电器且放电时，电池输出功率近似整机消耗，包含供电损耗；充电/外接电源时不提供此估算 |
| CPU 频率 | 每个 CPUFreq 调频域一个值；优先硬件报告，回退驱动报告；无权限则 `--` |
| GPU 频率 | 支持可读的 Qualcomm KGSL 与名称明确的 GPU devfreq 节点，其他设备可能不可用 |
| CPU/SoC/GPU 温度 | 自动匹配明确名称，支持手动选择；必须确认所选传感器实际含义 |
| CPU/GPU 独立功耗 | 预留可选项目，当前没有经过验证的机型数据源，显示 `--` |
| 应用 FPS / 帧间隔 | Shizuku 读取 SurfaceFlinger 指定前台图层的实际呈现时间戳；滑动窗口约 1 秒，高帧率时可能受系统 128 帧缓冲长度限制 |

Shizuku 的 shell 权限仍受 ROM 和 SELinux 约束，授权后不保证所有节点可读。手机重启后通常需要重新启动 Shizuku。若某个指标不可用，请在监控开启时复制“诊断”页内容，用于后续机型适配。

### 本机 GPU 与 FPS 适配结果

已在型号 `24122RKC7G`、SM8750、Android 16 / HyperOS `OS3.0.302.0.WOMMIXM` 上检查。GPU 的 `gpuclk`、`devfreq/cur_freq` 和 devfreq 目录对 shell 均返回 `Permission denied`，普通应用同样被拒绝。因此本版本会准确显示 ROM 权限限制，不能靠再次授权 Shizuku解除。未修改节点权限、SELinux 或系统安全设置。

FPS 在独立 SurfaceView 测试应用上实测：30 FPS 对应约 33.3 ms，60 FPS 对应约 16.7 ms。此指标是该图层的呈现帧率；插帧、视频 Surface、分屏、多图层游戏可能影响其与引擎内部渲染帧数的对应关系。诊断页展示实际选择的包名和图层。停留在 MurasameRTSS 设置页时显示 `--`，切回游戏后开始检测。

帧率只使用真实呈现时间戳，忽略 pending/0/重复时间戳；超过约 1 秒没有新帧时显示 0，缺少有效帧接口时显示 `--`。不会把系统刷新率当成应用 FPS。

本机充电时观察到电流符号与 Android 标准方向相反。方向校准依赖真实的未接电源放电状态，不通过修改系统电池状态模拟校准。双电芯的电压/电流口径仍以系统接口为准，不擅自乘 2。

字号特别大或竖屏特别窄时，单个过长指标会显示省略号；可调小字号或横屏查看完整核心频率。背景最大宽度不超过屏幕安全区域，不覆盖刘海挖孔。

应用设置中的预览在没有采样数据时明确标为“布局示例 · 非实测”；实际悬浮窗从不使用这些示例值。采样超时会清空读数，避免旧数据继续冒充实时数据。

## 触摸穿透的实现

仅使用一个 `TYPE_APPLICATION_OVERLAY` 窗口，同时设置 `FLAG_NOT_TOUCHABLE | FLAG_NOT_FOCUSABLE`。

Android 12+ 的整窗 alpha 取 `getMaximumObscuringOpacityForTouch() - 0.01`；用户选择的背景不透明度除以整窗 alpha 后作为背景画笔 alpha。这样背景实际不透明度跟随滑块，同时窗口整体满足平台的穿透条件。文字也受整窗 alpha 影响。

浮窗位置通过设置页调整，浮窗自身不提供拖动控件。未使用无障碍服务，也未关闭 Android 触摸安全机制。

应用内触摸测试页验证不可触摸标志、滑动和多指操作，但同 UID 存在平台豁免，不能单独证明跨应用穿透。0.2.0 和 0.2.1 额外使用独立 UID 的临时测试应用，在浮窗覆盖范围内注入点击，底层点击计数由 0 增至 1；测试应用已移除。真实游戏中的手指与多指操作仍建议实际确认。

## 构建

工程同时提供标准 Android Gradle 项目和无需 Gradle 下载的 Windows 本地构建脚本。源码采用 Java 17 和 Android 原生 UI，避免监控工具引入大量运行时依赖。

本次可用环境：JDK 21、Android SDK Platform 35、Build Tools 35.0.0。`compileSdk/targetSdk=35`，`minSdk=29`。若后续升级 SDK，重新验证前台服务与悬浮窗行为。

```powershell
# 在 PerfOverlay 目录执行，可使用本机现有 JDK / SDK
.\build.ps1 -Sdk 'A:\Android\android-sdk' -Jdk 'C:\Program Files\Android\openjdk\jdk-21.0.8'
.\test.ps1 -Jdk 'C:\Program Files\Android\openjdk\jdk-21.0.8'
```

构建脚本使用 SDK 自带 AAPT2、AIDL、D8、zipalign 和 apksigner，所有中间产物写入项目 `build/`，不会修改系统 SDK。输出 `dist/MurasameRTSS-1.4.1.apk` 和 SHA-256 校验文件。

也可在 Android Studio 中打开本目录，通过 AGP 8.13.0 / Gradle 8.13 构建。Shizuku 13.1.5 依赖已固定版本并随源码保存在 `vendor/`。

翻译源位于 `tools/localization.json`，生成的 Android 字符串资源随源码提供，不需要构建时联网下载翻译。

```powershell
python tools/generate_localization.py --check
# 编辑翻译后重新生成资源：
python tools/generate_localization.py
```

## 隐私与许可证

### 记录与删除

自动记录默认开启：开始监控即记录，停止监控即保存。关闭自动开关会结束当前记录，后续可以手动开始；手动结束后本次监控不会立即续录，下次开始监控仍遵循自动开关。结束记录后可继续保留浮窗。记录最快每秒一次，采样较慢时跟随采样频率；单次最多 21600 点，已有记录达到 256 MiB 后不再新建，需手动清理。隐藏浮窗仍记录；锁屏和暂停采样期间留空，解锁 / 恢复后继续。进程退出后数据仍在，单纯打开设置页不会自动启动监控或记录。

时间范围使用从记录开始计算的 `时:分:秒` 或直接秒数（例如 `10`），支持中文冒号；结束时间包含该秒内的全部采样点。删除会保留剩余点原始时间，不压缩时间轴；已删除、暂停和无效数据处不连线。删除不能撤销。仅删除单个采样点时，先点击图表选择它，再点删除。

记录保存在应用私有目录；逐点追加落盘，编辑采用同目录临时文件同步后原子替换，异常退出时忽略不完整的尾部采样。读取、保存、删除及统计在独立队列执行，曲线路径缓存复用。

记录期间采集全部已适配指标，不受浮窗显示开关限制。15 项曲线同时纵向排列，共用时间范围；点击或横向拖动一张图会同步其他图的游标和读数，CPU 各组分色显示。图表基于采集时的显示精度，受限指标留空并保存原因；旧记录中缺失的项目不会补造。电池侧功率曲线显示绝对值，选中采样点可查看充入 / 输出文字。卸载应用会清除记录。
